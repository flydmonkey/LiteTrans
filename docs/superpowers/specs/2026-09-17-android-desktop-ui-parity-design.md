# Android 界面：桌面风格 + 引导式三步

Android「轻转码」用桌面版的颜色和控件外观，但交互改成**一次只做一步**的引导，不把桌面那一长页缩到手机上。转码引擎、队列、选文件和输出逻辑不变。本设计只替换 [2026-09-16 Android 原生版](2026-09-16-android-native-transcoder-design.md) 里「界面」一节；其它章节继续有效。

## 背景

现网 Android 是 Material 3 动态取色，和桌面暖灰 / 墨色 / 橙色不是一套。用户先要求外观靠桌面，随后明确转码必须是引导式：

1. 添加文件、预览、裁切
2. 目标格式
3. 存放位置

## 目标与约束

- 一眼能认成「轻转码」：暖灰底、墨色字、橙色主按钮、深色 dock、圆角色块。
- 主路径严格三步，每屏只处理该步的事；用顶栏步骤指示当前在哪一步。
- 功能与现 Android 一致：相册 / 文件多选、探测、裁剪、预设 / 画质 / 分辨率、输出目录、单任务队列、取消 / 重试 / 打开 / 分享。
- 继续用 Jetpack Compose，不引入 WebView，不和桌面共享 React 代码。
- 只改 `ui/`（含 `theme/`）和窗口背景。`domain` / `engine` / `data` / `TranscodeService` 不为此改语义。
- 中文以桌面为准；相册、分享、通知权限用现有 Android 用词。

## 方案

固定浅色主题 + 三步引导 Compose。颜色和圆角从 `src/App.css` 抄死。禁止动态取色，不跟随系统深色模式。

不采用：桌面一页全展开、只换 Material 配色、WebView 套 React。

## 引导壳

全程顶栏：左「轻转码」，右胶囊「不上传 · 不联网」。其下三个步骤块 `1 添加` `2 格式` `3 存放`，当前步墨色实心，未完成浅底，已走过可点回去。

有 `message` 时在顶栏下显示黄底提示条，「知道了」关闭。

底部固定深色 dock，文案随步骤变：

| 当前步 | 左摘要 | 右按钮 |
| --- | --- | --- |
| 1 | 已选几个文件，或「先添加源视频」 | 「下一步」；没有可导入文件时禁用 |
| 2 | `源格式 → 目标`，以及画质 / 分辨率摘要 | 「下一步」 |
| 3 | 将几个文件转到某格式、存到哪 | 「开始转码」；进行中为「正在加入队列…」/「正在转码…」 |

返回：第 2 / 3 步 dock 左侧或顶栏提供「上一步」。系统返回键：第 2 / 3 步退回上一步，第 1 步走系统默认（不直接退出转码服务）。

## 第一步：添加、预览、裁切

标题「添加文件」，副标题「预览并裁切要保留的片段」。

- 虚线添加区：无拖放。文案「添加要转码的视频」/「一次能选好几个」。两个深色按钮「相册」「文件」，分别走 `PickMultipleVisualMedia` 与 `OpenMultipleDocuments`。
- 文件列表：文件名 +「容器 · 编码 · 宽高 · 帧率 · 时长」。探测中「正在读取格式…」。不可导入红底行。未在转码的可「移除」。
- 点一条有时长的源即选中（黑边白底）。主区域显示预览：系统能播的用 Media3；不能播的只留时间轴，**不用** FFmpeg 出预览片。
- 时间轴对齐桌面：浅轨、墨色选区、橙色手柄与播放头。「设为开始」「设为结束」「恢复整段」。已裁剪的文件旁标明「已裁剪」。

没有可导入文件时不能进入第二步。

## 第二步：目标格式

标题「转成」，副标题桌面同款 `源格式 → 目标`。

- 格式两列网格。默认四张常用卡（`mp4-h264`、`mp4-copy`、`mp4-h265`、`mov-h264`）加虚线「更多」。选中非常用项时第四张换成该项（与桌面 `collapsedPresetCards` 相同）。展开后虚线卡改「收起」。
- `mp4-copy` 只显示「不重编码只换文件外壳…」说明，不显示画质 / 分辨率。
- 其它视频预设：画质（原画 / 标准 / 节省体积）和分辨率（原尺寸 / 1080p / 720p / 480p）两组带 hint 的 chip。
- 音频预设只显示音质。

本步不出现输出目录、不出现开始转码。

## 第三步：存放位置

标题「输出到」，默认「下载/轻转码」，按钮「换个位置」走现有 SAF 目录选择。

有任务时在位置下方列出队列：源 → 输出、状态 / 进度 / 错误、橙色进度条；取消 / 再试一次 / 打开 / 分享；「清空已完成」。

点「开始转码」才入队。第一次仍请求通知权限，被拒也继续转码。转码过程中可留在本步看进度，也可回到第 1 / 2 步改尚未开转的源或格式；正在转码的文件仍不可移除。

## 模块边界

| 单元 | 做什么 | 怎么用 | 依赖 |
| --- | --- | --- | --- |
| `ui/theme` | 固定浅色令牌，关闭动态取色 | `LightTranscodeTheme` | Compose |
| `ui` 展示组件 | 步骤指示、添加区、预览/裁剪轨、预设卡、chip、输出条、任务行、dock | 由 `AppScreen` 组装 | theme |
| `AppScreen` | 三步状态、选择器、通知权限 | Activity `setContent` | ViewModel |
| `AppViewModel` | 现有状态与操作 | 不改领域语义；当前步和选中源用界面状态 | 现有 |

独立全屏 `TrimScreen` 取消，裁剪只出现在第一步。

## 错误与空态

提示条、探测失败、不可导入、输出目录不可写，沿用现有中文映射。第 1 步无文件时「下一步」禁用，摘要「先添加源视频」。不把用户送进空的第 2 / 3 步。

## 测试

- 现有 JVM 单元测试必须继续通过。
- 抽出可测纯函数并加 JUnit：步骤是否可前进（无导入文件不能进第 2 步）、折叠预设列表、`mp4-copy` 隐藏分辨率、各步 dock 按钮文案。
- 仪器测试不改为截图对比。真机冒烟：三步能走完；预览/裁切在第一步；开始转码只在第三步。

## 成功标准

侧载后是浅色暖灰 + 橙色主按钮，不再被壁纸染色。打开 App 先添加/预览/裁切，再选格式，最后选存放位置并开始。转码结果与改 UI 前一致。

## 明确不做

- WebView / 共享 React
- 一页同时展示三步内容（桌面那种长页）
- 跟随系统深色模式或动态取色
- 用 FFmpeg 生成裁剪预览片
- 改转码参数、队列、输出命名
- iOS

# 桌面端：对齐手机功能，保留桌面壳

把现网 iOS / Android 已有的转换 / 历史 / 我的、视频 / 音频 / 文档、局域网和多语言接到现有 Tauri 桌面应用上。视觉和交互继续走桌面，不搬手机底栏或设置子页。

产品语义以手机为准，不另写一套预设表：

- [音频转换](2026-09-17-android-audio-conversion-design.md)
- [文档转换](2026-09-17-android-document-conversion-design.md)
- [多语言](2026-09-17-android-i18n-design.md)
- [局域网媒体库](2026-09-17-android-lan-media-library-design.md)
- [iOS 视频合并](2026-09-18-ios-video-merge-design.md)

HIG：[Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)、[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)、[Split views](https://developer.apple.com/design/human-interface-guidelines/split-views)。Windows / Linux 用同一套 Web 壳，不接系统原生 Settings 窗口。

## 背景

桌面是 Tauri + React + 捆绑 FFmpeg，目前单页：源视频 → 格式 → 队列。只有视频（外加抽 MP3 / M4A），任务在内存里，关窗口即丢。iOS / Android 已经是三入口 + 三种转换模式 + 持久化历史 + 局域网。

## 目标与约束

- 手机能转的视频 / 音频 / 文档，桌面也能入队并写出对应文件。
- 文件留在本机。不上传、不联网转码。局域网默认关。
- 外观继续现有暖灰 / 墨色 / 橙色（`src/App.css` 令牌），不跟系统深色，不用 Material 动态取色，不做 iOS Settings 灰。
- 仍是 Tauri + React + Rust。不与手机共享代码，不互相同步设置或历史。
- 窗口默认 `1180×780`，最小约 `880×640`。macOS / Windows / Linux 同一套界面。

## 方案

侧栏三个平行目的地（转换 / 历史 / 我的）+ 转换页左右分栏（文件 | 格式）。格式、画质、分辨率、输出都留在转换页，不 push 子页。队列从转换页挪到历史。一条队列：音视频走 FFmpeg，文档走独立引擎。

不采用：底栏 Tab、手机「首页摘要 + 设置子页」、把现有一长页原样塞进更窄窗口、单独的 macOS Settings 窗口。

## 模块边界

| 单元 | 做什么 | 怎么用 | 依赖 |
| --- | --- | --- | --- |
| `src/` 壳 | 侧栏、转换 / 历史 / 我的、i18n | 现有 React 入口 | `src/api.ts` |
| Domain（Rust 纯函数） | 预设表、开始条件、历史分段、页范围 | 命令与测试共用 | 无 |
| 队列泵 | 单任务、`.partial` 再改名 | 入队后跑 | FFmpeg sidecar、文档引擎 |
| JobStore | `jobs.json` 读写 | 历史、局域网只读 | 配置目录 |
| 会话 | 三模式预设 / 输出目录、语言、局域网 | `settings.json` | 配置目录 |
| 局域网 HTTP | 只读媒体库 | 开关打开时听局域网 IPv4 | JobStore |

## 窗口骨架

```
┌──────────┬─────────────────────────────────────────────┐
│ 轻转码    │  内容区（当前侧栏项）                          │
│  转换    │                                             │
│  历史 2  │                                             │
│  我的    │                                             │
└──────────┴─────────────────────────────────────────────┘
```

- 侧栏约 176px，可拖到 148–240px。当前项墨底浅字。切走再回来，转换页的文件、裁切、三份会话都还在。
- 「历史」角标 = 全部模式里排队 + 进行中的条数。
- 「我的」在局域网运行时不打数字角标；局域网这一行显示「已开启」。
- 窄于 960px：侧栏收成图标轨；转换页左右栏改上下叠，顺序仍是文件 → 格式 → 开始。
- 不要底栏。转换页底部 dock（摘要 + 开始）钉在内容区底部，不伸进侧栏。历史页和「我的」没有这条 dock。

## 转换工作区

内容区顶上分段：**视频 | 音频 | 文档**。三份 `WizardSession` 互相独立。

```
┌─────────────────────────────────────────────────────┐
│  [ 视频 ]  音频   文档                               │
├────────────────────────┬────────────────────────────┤
│ 拖放 / 选择文件         │ 格式卡 / 画质 / 分辨率      │
│ 预览 / 裁切             │ 输出目录                    │
│ 文件列表                │                            │
└────────────────────────┴────────────────────────────┘
│ 摘要                                      [开始…]   │
└─────────────────────────────────────────────────────┘
```

拖放和「选择文件」都按**当前模式**过滤。类型不对的文件不进列表，顶栏提示「这个模式加不了这种文件」。

输出始终是选文件夹（默认「下载 / LiteTrans」），不搬相册 / 音乐 / 文件 App。三种模式可记不同目录。

点「开始」且真正入队后：

1. 只清空**当前**模式的源文件。
2. 历史分段切到该模式对应段。
3. **窗口仍停在转换页**。侧栏「历史」出角标。不强制跳历史。

入队失败则留在本页，出提示条。

开始条件与手机 `canStart` 相同：可导入数量达标、探测完成、没有进行中任务、输出目录可用。合并另加：2…20 段，且不能有标红文件。

视频按钮文案「开始转码」；音频 / 文档「开始转换」。入队中 / 进行中禁用，文案为「正在加入队列…」/「正在转换…」。

### 视频

常用卡：`mp4-h264`、`mp4-copy`、`mp4-h265`、`mov-h264`、`video-concat`（合并）。「更多」：MKV H.264 / H.265、WebM VP9、AVI MPEG-4、GIF。视频模式不再放 MP3 / M4A。

- `mp4-copy`：无画质、无分辨率、无裁切。
- `video-concat`：无分辨率、无裁切；列表可拖排序；至少 2 个、最多 20 个可导入；一条 Job、一个输出 `{第一条 stem}-merged.mp4`；画幅跟第一条，竖横混拼有黑边。规则对齐 [iOS 视频合并](2026-09-18-ios-video-merge-design.md)。
- 其余视频：画质（原画 / 标准 / 节省体积）和分辨率（原尺寸 / 1080p / 720p / 480p）；有时长则可裁切。

### 音频

格式一次铺开：`audio-mp3`、`audio-aac`、`audio-wav`、`audio-flac`、`audio-ogg`、`audio-amr`。WAV / FLAC 不显示音质。可裁切。无分辨率。源可以是音频，也可以是带音轨的视频。

### 文档

先选文件，右栏只出现该 `DocumentSourceKind` 能转的目标。一批必须同类型；混选提示「请一次只加同一种文件」，已选保留、新文件不进入。

| 源 | 预设 | 左栏 |
| --- | --- | --- |
| 图片 | `image-jpg` / `png` / `webp` / `bmp` / `gif` / `image-compress` | 图预览；仅压缩显示画质 |
| PDF | `pdf-image` / `pdf-txt` / `pdf-compress` / `pdf-split` | 页预览 + 页范围（1-based 闭区间） |
| Word（`.docx`） | `office-pdf` | 只显示文件名 |
| Excel、旧 `.doc` / `.xls` | 无 | 行标红，不能开始 |

`pdf-image` 另选容器：`jpg` / `png` / `webp`，写入 `OutputConfig.container`。每个源文件一条任务；一个 PDF 转出多页仍是一条，`outputPaths` 为全部输出，`outputPath` 为第一份。

文档不走 FFmpeg。默认输出仍是用户选的文件夹（桌面不按「图片进相册、PDF 进文档」分流）。

## 历史

顶上分段：**视频 | 音频 | 文档**。只渲染当前段。新任务在上。分段规则与手机 `historySegmentFor` 相同。

有进行中任务时，分段下显示「正在转换 n 个 · 点这里回转换」；点了回到转换页并切到对应模式。没有进行中则不出现该条。

转换页上的「第 3 步 · 转码队列」删除。进度、取消、打开改在历史里。

### 行与操作

标题：`displayName`（默认输出文件名）。副标题：`源格式 → 目标 · 状态 · yyyy-MM-dd HH:mm`。失败时副标题为错误原因。多份输出追加「n 张图片」或「n 个 PDF」。进行中显示进度条和现有 ETA。

| 状态 | 主按钮 | 更多（右键或「更多」） |
| --- | --- | --- |
| 排队 / 进行中 | 取消 | 无 |
| 失败 / 已取消 | 再试一次 | 删除 |
| 完成 | 打开 | 在文件夹中看、重命名、删除 |

双击完成行 = 打开。Enter：完成则打开，失败 / 已取消则重试。Delete：删除（有确认）。Esc：关掉对话框。多份输出时，「打开」和「在文件夹中看」都针对第一份仍存在的文件。

桌面用「在文件夹中看」代替手机「分享」。

### 清空、删除、重命名

- **清空已完成**：只清当前分段里已结束的任务。弹一次确认：「清空这一段里已结束的记录？文件仍留在磁盘上。」
- **删除**：从列表去掉，并删除该任务全部 `outputPaths`（缺则 `outputPath`）。先确认。
- **重命名**：改 `displayName`，并尝试重命名磁盘上第一份输出；多份输出不批量改名。

清空不删磁盘文件。删除才删。

### 空态

「还没有视频记录」/ 音频 / 文档 三种句式。按钮「去转换」切到转换页并带上对应模式。

## 我的

侧栏选「我的」后，内容区再分两栏：左设置项、右当前项。默认选中「局域网访问」。切走再回来仍停在上次那一项。不要 push 子页，不要单独的系统偏好窗口。

分组：

1. 局域网访问、语言
2. 隐私协议、使用条款
3. 关于

不放输出目录、不清历史。页脚：应用名「轻转码」、版本号、「不上传 · 不联网」。

### 局域网访问

桌面当服务器：同一网的浏览器可看历史、播放、下载。默认关。网页只读。不提供上传、删除、重命名、开始转码。

| 控件 | 行为 |
| --- | --- |
| 开关 | 默认关。打开后在局域网 IPv4 上听端口（优先 `17890`，连试 10 个） |
| 口令 | 可留空；保存去首尾空白；有口令则所有请求带 `?k=` |
| 地址 | 开关开且有局域网地址时显示；有口令则带编码后的 `k=` |
| 复制 | 写入剪贴板 |
| 在浏览器打开 | 本机打开该地址 |

没有局域网地址（有线或 Wi‑Fi 均可）：开关可拨开，但不听端口，文案「没有可用的局域网地址」。端口都被占：提示失败原因。关掉开关或退出应用：服务停。下次启动若开关仍开且有地址，再拉起；口令不变。不上开机自启。绑定局域网 IPv4，不听 `0.0.0.0`。

网页、路由、分段对齐 [局域网媒体库](2026-09-17-android-lan-media-library-design.md)：`GET /`、`GET/HEAD /m/{id}`、`GET/HEAD /d/{id}`（可选 `/{index}`）。视觉用桌面暖灰 / 橙色。口令恒等比较（先 URL 解码）。

### 语言

单选，立刻换界面：跟随系统（默认）、简体中文、繁體中文、English、日本語、한국어。系统对不上这五种时用英文。映射与 [多语言](2026-09-17-android-i18n-design.md) 相同。语言名用该语言自己的写法；「跟随系统」跟当前界面语言。不与手机同步。

`settings.json` 的 `language` 取值：`system`、`zh-Hans`、`zh-Hant`、`en`、`ja`、`ko`。界面、错误、局域网 HTML 都走解析后的当前语言。预设代号（MP4、H.264）保持拉丁文。现有写死中文全部进 `src/locales/{en,zh-Hans,zh-Hant,ja,ko}.json`，缺键回退英文。

### 隐私、条款、关于

三页都是应用内正文，不依赖联网。隐私、条款底部可「在浏览器中打开」`https://flydmonkey.github.io/LiteTrans/docs/privacy.html` 与 `terms.html`，打不开不挡阅读。关于：大标题「轻转码」、版本号、「不上传 · 不联网」，以及本机工具说明。

## 数据

任务持久化到应用配置目录 `jobs.json`（原子写：先写 `.tmp` 再替换）。字段在现有 `Job` 上增加并与手机对齐：

- `displayName`、`outputPaths`、`createdAtEpochMs`
- 合并：`concatSourcePaths`（有序，含第一段；缺省 `[]` 表示不是合并）
- PDF：`MediaInfo.pageCount` / `pageStart` / `pageEnd`

`settings.json` 增加：三模式各自的 `preset` / `quality` / `size` / `outputDir`；`language`；`lanShare.enabled` / `lanShare.token`。源文件列表只留在当前进程：切侧栏不丢，重启后转换页是空的，历史仍在。

启动时：状态为排队或进行中的任务改为失败，错误「上次退出时中断」，可重试。已完成记录保留。

默认输出目录仍是「下载 / LiteTrans」；三种模式缺省都指向它，用户改过则分开记。

探测、选文件过滤随模式变。拖放在 Rust 命令里按模式校验。

## 引擎

同一时间只跑一条。泵取出队头：文档预设走文档引擎，其余走现有 FFmpeg（macOS 上 H.264 / H.265 仍优先 VideoToolbox）。

| 能力 | 做法 |
| --- | --- |
| 现有视频预设 | 不动 |
| `video-concat` | 每段先转到对齐后的临时 MP4，再 concat；失败清临时文件；源不动 |
| `audio-wav` / `flac` / `ogg` / `amr` | 扩 `resolve_config`，与 MP3 / M4A 同一条泵 |
| 图片互转 / 压缩 | 本机解码写出 |
| PDF 转图片 / TXT / 压缩 / 拆分 | 文档引擎 |
| Word → PDF | 文档引擎 |

未知预设入队失败，文案「未知预设」。`.partial` 再改名规则不变。

## 错误

转换页和历史页顶上共用一条黄底提示，点「知道了」才关，不自动消失。探测失败、类型不对、合并条数不够、混选文档、没有输出目录、局域网没地址或端口被占，都走这里。不把 FFmpeg 整段日志抛给用户。失败任务行内副标题仍是该条原因。

## 测试

- Domain 纯函数：预设显隐、`canStart`、历史分段、清空只清当前段、删除带上全部 `outputPaths`、合并 1 段不可 / 2 段可 / 超过 20 不可。
- 命令：入队、取消、重试、持久化、启动把中断任务标失败、局域网口令与路由。
- 界面：侧栏三栏、三模式会话互不覆盖、开始后留在转换页且历史有角标。
- 现有 `npm run smoke` 与桌面转码测试继续通过。
- 不在 CI 跑真实长片；本机冒烟：视频转码、音频抽取、两段合并、一张图转 JPG、局域网浏览器能打开。

## 落地顺序

写实现计划时按四刀切，每刀可单独用：

1. 壳：侧栏、历史页、我的根页（语言 / 关于 / 法律正文）、任务持久化、i18n。现有视频转码改在新壳里跑。
2. 音频模式 + 视频合并。
3. 文档。
4. 局域网。

## 明确不做

- 和手机同步设置或历史
- Excel 转 PDF、OCR、云上传
- 开机自启、托盘常驻、多窗口
- 菜单栏列出全部命令（可后补，本规格不要求）
- 网页上改记录、HTTPS、公网穿透、mDNS
- 格式 / 画质改成手机子页
- 动态取色、跟随系统深色
- ⌘, 打开独立 Settings 窗口

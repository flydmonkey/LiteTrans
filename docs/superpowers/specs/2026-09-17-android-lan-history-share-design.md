# Android 局域网访问历史记录

在「我的」里增加可选的本机 HTTP 服务，让同一局域网的浏览器查看转码历史并下载已完成文件。叠在现有历史三分段和 `JobStore` 上。默认关闭。不上传、不走公网、不改记录。

## 目标

- 「我的」列表最上方增加 **局域网访问** 入口，进入独立页。
- 页内开关默认 **关**。打开后前台服务常驻通知，关掉开关或停止该通知则停 HTTP。
- 口令 **可自己设，可留空**。留空则同网知道地址即可访问；填写则所有请求必须带该口令。保存时去掉首尾空白，若仍为空则视为无口令。口令会记住，开关或重启 App 不自动更换。
- 网页只读：按 **视频 | 音频 | 文档** 列出历史。已完成且文件仍在的可下载。
- 不提供上传、删除、重命名、开始转码。

## 方案

独立前台服务 `LanShareService`，与 `TranscodeService` 分开。轻量 HTTP（不引入 Ktor）。监听本机端口，页面只读 `JobStore`，下载只允许任务记录里的输出路径。

```
我的
  └ 局域网访问（开关 + 口令 + 链接）
LanShareService（通知常驻）
  └ HTTP GET /、GET /d/{id}、GET /d/{id}/{index}
```

不采用：挂进转码服务、Ktor、随机口令每次更换、开机自启、HTTPS / 公网穿透、网页改记录。

## 设置

```
data class LanShareSettings(
    enabled: Boolean,   // 默认 false
    token: String,      // 默认 ""；空白视为无口令
)
```

持久化（DataStore 或独立 preferences）。`enabled` 与 `token` 分开存。

- 打开开关：若当前有可用局域网 IPv4，则启动服务并通知；否则保持意图为开，页面提示先连 Wi‑Fi / 热点，**不听端口**。连上后再拉起。
- 关闭开关：停服务、撤通知。
- 用户从系统通知停止该服务：视为关闭，写回 `enabled = false`。
- 进程被杀后：`START_STICKY` 或下次进入 App 时，若 `enabled` 仍为 true 且有局域网地址，再拉起。口令不变。
- 手机重启：服务不自动起来。下次打开 App，若开关仍是开的，再拉起（口令不变）。不上开机广播。

口令在服务运行中被改写：立即生效，旧 `k=` 返回 401。空口令立刻变成无校验。

## 手机界面

「我的」根列表：

1. 局域网访问  
2. 隐私协议  
3. 使用条款  
4. 关于  

局域网访问页（`MinePage.LanShare`）：

| 元素 | 行为 |
| --- | --- |
| 开关 | 局域网访问，默认关 |
| 口令 | 单行输入，提示「可留空」；失焦或确认后保存 |
| 地址 | 仅开关开且有局域网 IP 时显示 `http://{ip}:{port}/`；有口令则带 `?k=`（URL 编码）。可复制 |
| 无网提示 | 未连 Wi‑Fi / 热点时说明先连上 |

通知文案：「局域网访问已开启」。点通知打开本页。

无障碍：开关有开关语义，不要做成只能点整行进子页却找不到开关。

## 网络与绑定

- 权限：`INTERNET`；读地址用 `ACCESS_WIFI_STATE` / `ACCESS_NETWORK_STATE`。
- 前台服务类型与现有转码服务一致方向：`dataSync`（侧载，不走 Play 的 specialUse 声明）。
- 端口：优先 `17890`，被占用则 `17891` 起顺延，最多尝试 10 个；全占用则页面报错、开关保持开但无地址。
- 只在存在非回环 IPv4（Wi‑Fi 或热点共享）时 `bind`。不把地址写成 `127.0.0.1` 给用户当局域网链接。
- 展示第一个可用 IPv4。多网卡时以 Wi‑Fi 接口优先。
- HTTP，无 TLS。v1 不做 mDNS 主机名。

## HTTP 接口

所有路由只接受 GET。有口令时，必须带查询参数 `k=`，与已保存 token **恒等比较**（查询值先 URL 解码）。无口令时忽略多余的 `k=`。地址栏展示时对 `k` 做 URL 编码。

| 方法 | 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| GET | `/` | `200` `text/html` 历史页 | 口令错 `401` |
| GET | `/d/{jobId}` | `200` 文件流，`Content-Disposition` 附件 | 口令错 `401`；任务不存在/未完成/无主文件 `404` |
| GET | `/d/{jobId}/{index}` | 多输出中的第 `index` 份（从 0 起） | 同上；越界 `404` |

其它路径 `404`。POST/PUT/DELETE `405`。

下载约束：

- 仅 `JobStatus.Completed`。
- 文件路径必须是该任务 `outputPaths`（若空则回退 `outputPath`）里的某一项，且当前仍是普通文件。
- 拒绝 `..`、绝对路径拼接到应用目录之外、符号链接逃逸。打开文件用记录中的绝对路径，不再拼接用户输入的路径段。
- `Content-Type` 按扩展名猜测；未知则 `application/octet-stream`。
- 文件名用任务展示名或路径 basename，做 RFC 5987 文件名头，避免换行注入。

不把 `Job.sourceUri`、内部绝对路径原文写进 HTML 可见文本（下载由 id/index 间接引用即可）。列表展示：`displayName`、容器/预设、状态文案。

## 网页

单页 HTML，无外链脚本。视觉靠近 App 浅色底（`#ecece8` / 深字 / 强调色 `#c45a2a`），不做成营销站。

三段：**视频**、**音频**、**文档**。分组规则与 App 相同：`isDocumentHistoryJob`、`isAudioHistoryJob`，其余为视频。每段内新任务在上。

每行：文件名、格式、状态。可下载时出「下载」链接（多文件出多个，带序号或文件名）。排队、进行中、失败、已取消、文件缺失：无下载，可附一句短状态。

空段：「还没有视频记录」等同 App 空态文案。

下载链接带同一 `k=`（若有口令）。

## 安全

- 默认关。
- 无口令等于同局域网任意客户端可读可下；页面用一句说明写清。
- 不鉴权管理接口。不目录遍历。不代理任意 URL。
- 不在日志里打出口令明文。
- 本功能仍不是「上传到服务器」：流量只到用户指定的局域网对端。隐私协议补一句：用户主动打开局域网访问后，同一网络里持有地址（及口令，若设置了）的设备可以查看历史并下载已完成文件；转码本身仍不要求联网。

## 错误

| 情况 | 表现 |
| --- | --- |
| 开关关 / 服务停 | 浏览器连不上 |
| 无局域网地址 | 页内提示；不 listen |
| 口令错误或缺失（已设口令） | `401` 纯文本「需要正确口令」，无任务列表 |
| 文件没了 | `404` |
| 端口全占用 | 页内错误，不静默当成功 |

## 测试

纯函数优先（不启真端口也可测路由与鉴权）：

- 默认 `enabled == false`，`token == ""`。
- 空口令：无 `k=` 可通过；有口令：缺/错 `k=` 拒绝，对则通过。
- 历史分组与 App 三段一致。
- 仅 Completed 且路径在任务输出列表内可下载。
- `..`、伪造 id、未完成任务拒绝。
- 关闭开关后停止监听（仪器测试或服务单元里 mock server lifecycle）。

# 桌面第 2–3 刀：音频、文档、视频合并

在已落地的桌面壳（侧栏转换 / 历史 / 我的、任务持久化、五种语言）上，接上手机已有的音频转换、文档转换和视频合并。产品语义不另写一套，以 [桌面端对齐规格](2026-09-19-desktop-mobile-parity-design.md) 的转换工作区、音频、文档、视频合并、历史、数据、引擎各节为准。

本规格只固定这一批的范围和接法。局域网仍按原规格第 4 刀，本刀不做。

## 背景

第 1 刀已经把视频转码放进两栏转换页，历史按视频 / 音频 / 文档分段，MP3 / M4A 仍挂在视频页。手机端音频六种格式、文档引擎、`video-concat` 都已有规格和实现。桌面还缺模式分段、三份会话、合并入队，以及独立文档引擎。

## 目标与约束

- 转换页顶上 **视频 | 音频 | 文档**。三份会话互不影响：源文件、预设、画质 / 分辨率或页范围、输出目录、裁切。切侧栏或切模式不丢；关窗口后转换页清空，历史仍在。
- 点「开始」且真正入队后：只清空**当前**模式的源；窗口留在转换页；历史角标；历史分段切到对应段。
- 视频按钮「开始转码」；音频 / 文档「开始转换」。
- 输出都进用户选的文件夹（默认「下载 / LiteTrans」）。桌面不按「图片进相册、PDF 进文档」分流。
- 外观继续暖灰 `#ecece8` / 墨 `#1f2428` / 橙 `#c45a2a`。不跟系统深色。
- 不与手机同步设置或历史。不上传。
- `android/`、`ios/` 不改。

## 方案

一条队列、两种跑法。泵取出队头：文档预设走新的 Rust `document` 模块，其余走现有 FFmpeg（macOS 上 H.264 / H.265 仍优先 VideoToolbox）。未知预设入队失败，文案「未知预设」。

不采用：文档也绑 FFmpeg / ImageMagick；不重编码 concat demuxer；文档单独队列；先做局域网。

## 转换页

### 视频

常用卡：`mp4-h264`、`mp4-copy`、`mp4-h265`、`mov-h264`、`video-concat`。「更多」：MKV H.264 / H.265、WebM VP9、AVI MPEG-4、GIF。**视频模式不再放 MP3 / M4A。**

- `mp4-copy`：无画质、无分辨率、无裁切。
- `video-concat`：无分辨率、无裁切；列表可拖排序；至少 2 个、最多 20 个可导入；任一段标红则整单不能开始。一条 Job、一个输出 `{第一条 stem}-merged.mp4`（冲突走现有 `-001`）。`concatSourcePaths` 含第一段、与列表顺序一致。画幅跟第一条（偶数化），帧率缺则 30；每段先转到对齐后的临时 MP4 再 concat；竖横混拼有黑边；失败清临时文件；源不动。
- 其余视频：画质（原画 / 标准 / 节省体积）和分辨率（原尺寸 / 1080p / 720p / 480p）；有时长则可裁切。

### 音频

格式一次铺开：`audio-mp3`、`audio-aac`、`audio-wav`、`audio-flac`、`audio-ogg`、`audio-amr`。WAV / FLAC 不显示音质。可裁切。无分辨率。源可以是音频，也可以是带音轨的视频。没有音轨则入队时跳过并提示。

### 文档

先选文件，右栏只出现该 `DocumentSourceKind` 能转的目标。一批必须同类型；混选提示「请一次只加同一种文件」，已选保留、新文件不进入。

| 源 | 预设 | 左栏 |
| --- | --- | --- |
| 图片 | `image-jpg` / `image-png` / `image-webp` / `image-bmp` / `image-gif` / `image-compress` | 图预览；仅压缩显示画质 |
| PDF | `pdf-image` / `pdf-txt` / `pdf-compress` / `pdf-split` | 页预览 + 页范围（1-based 闭区间） |
| Word（`.docx`） | `office-pdf` | 只显示文件名 |
| Excel、旧 `.doc` / `.xls` | 无 | 行标红，不能开始 |

`pdf-image` 另选容器：`jpg` / `png` / `webp`，写入 `OutputConfig.container`。每个源文件一条任务；一个 PDF 转出多页仍是一条，`outputPaths` 为全部输出，`outputPath` 为第一份。

探测、选文件、拖放按当前模式过滤。类型不对的不进列表，顶栏黄条提示（点「知道了」才关）。

开始条件与手机 `canStart` 相同：可导入数量达标、探测完成、没有进行中任务、输出目录可用。合并另加：2…20 段，且不能有标红文件。

## 引擎

| 能力 | 做法 |
| --- | --- |
| 现有视频预设 | 不动 |
| `video-concat` | 每段先转到对齐后的临时 MP4，再 concat；失败清临时文件 |
| `audio-wav` / `flac` / `ogg` / `amr` | 扩 `resolve_config`，与 MP3 / M4A 同一条泵 |
| 图片互转 / 压缩 | 本机解码写出 |
| PDF 转图片 / TXT / 压缩 / 拆分 | 文档引擎 |
| Word → PDF | 文档引擎，只处理 `.docx` |

文档不走 FFmpeg。不把 FFmpeg 或引擎整段日志抛给用户。`.partial` 再改名规则不变。

## 历史与设置

历史顶上分段仍是视频 / 音频 / 文档。音频预设进音频段，文档预设进文档段，合并进视频段。从历史「去转换 / 回转换」切到对应模式。

多份输出：打开和「在文件夹中看」针对第一份仍存在的文件；副标题可带「n 张图片」或「n 个 PDF」。清空 / 删除 / 重命名与第 1 刀相同。

`settings.json` 为三种模式各记 `preset` / `quality` / `size` / `outputDir`。语言沿用第 1 刀。本刀界面不出现局域网。

## 测试

- Rust 纯函数：预设显隐（视频无 MP3/M4A、音频六种铺开、文档随源类型）、`canStart`、合并 1 段不可 / 2 段可 / 超过 20 不可、文档混选拦住、页范围钳制。
- 命令：音频入队、合并一条 Job、文档入队写出 `outputPaths`、泵把文档任务交给文档引擎。
- 前端：`npx tsc --noEmit`、`node scripts/check-locales.mjs`。
- 现有 `npm run smoke` 继续通过。
- 本机冒烟：抽一段音频、两段合并、一张图转 JPG、一个 PDF 拆分。

## 范围外

- 局域网 HTTP
- 转场、配乐、画中画、单段裁切后再合并
- OCR、联网转换
- Excel / 旧 `.doc` 转 PDF
- 文档单独队列或插队
- 改 `android/`、`ios/`

## 落地

从当前桌面壳分支继续做，开新分支实现本规格。实现计划覆盖音频 + 合并 + 文档，一次交付可单独使用；局域网另开计划。
